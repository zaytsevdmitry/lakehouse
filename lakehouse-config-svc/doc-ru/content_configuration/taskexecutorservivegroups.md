# Группа исполнителей задач
Это специальный маркер для конфигурации задач. По этому маркеру исполнитель может понять, что задача предназначена для него (группы в которую он входит).
Используется как механизм маршрутизации задач. К примеру сами исполнители могут быть оснащены разным функционалом или даже написаны на разных языках.
Помечая изадачу и исполнителя одним и тем же маркером, можно получить эффект маршрутизации или управления очередями.

## Поля объекта
| Поле | Назначение                    |
| :--- |:------------------------------|
| keyName | Уникальный идентификатов      | 
| description | Описание для документирования | 
| domainKeyName | Домен, которому принадлежит группа. Выводится из репозитория, из которого загружен файл, и **проставляется в момент синхронизации** (`GitOpsSynchronizer.stampDomainOn(...)`), а не берётся из содержимого файла. `null` для группы, созданной через REST API. Не часть идентичности: `keyName` остаётся единственным первичным ключом |
| allowedDomains | Дополнительные домены, задачи которых группа вправе обслуживать. Хранятся в коллекционной таблице `task_execution_service_group_domains` (колонка `domain_name`). Пустой список означает «только собственный домен» |

## Домены
Группа несёт домен в двух независимых ролях:

- **Владение** — `domainKeyName` показывает, из какого репозитория загружена группа. Как и у любого
  управляемого объекта, домен не записывается в YAML-файл: он выводится из репозитория и всегда
  побеждает любое значение разобранного объекта. Один и тот же `keyName` не может существовать в двух
  доменах, а REST-обновление, которое перезаписало бы группу одного домена группой другого,
  отклоняется с `DomainConflictException` → `409 Conflict`.
- **Возможность** — `allowedDomains` это список доменов, задачи которых исполнители этой группы могут
  дополнительно выполнять. Домен самой группы разрешён неявно всегда.

`lakehouse-scheduler-svc` обеспечивает эту возможность при публикации задач
(`ScheduleTaskInstanceService.checkDomain(...)`): если домен расписания не входит в
`allowedDomains ∪ {domainKeyName}`, экземпляр задачи сохраняется со статусом `CONF_ERROR`,
отложенное сообщение продюсера удаляется и в Kafka ничего не отправляется. Именно этот механизм не
пускает чужой домен в группу исполнителей, потому что сами исполнители группируются только по
`taskExecutionServiceGroupName` (это Kafka `group.id`) и о доменах ничего не знают. См.
[scheduler-svc: Домены](../../../lakehouse-scheduler-svc/doc-ru/readme.md#домены) и
[Домены](domains.md).

**Пример**
```json
{
  "name": "spark-cluster",
  "description": "Spark job group",
  "allowedDomains": ["analytics"]
}

```
